# Mekan — недвижимость и CRM

Дипломный проект **«Разработка интеллектуальной системы управления недвижимостью и клиентами»**.

Монорепозиторий с отдельными frontend и backend, общими контрактами, REST API и интерфейсом на русском, английском и туркменском языках.

## Быстрый запуск

Требуется **Node.js 24+** и npm. Из корня репозитория:

```sh
npm ci
npm run dev
```

- **Frontend:** http://127.0.0.1:5173
- **Backend:** http://127.0.0.1:3000/api/v1/health
- **Swagger UI:** http://127.0.0.1:3000/docs/
- **OpenAPI JSON:** http://127.0.0.1:3000/docs/json

При первом входе создайте администратора. После этого открытая регистрация закрывается, сотрудников добавляет администратор через раздел «Команда». Готовых паролей и демонстрационных персональных данных нет.

Frontend в режиме разработки отправляет `/api` и `/docs` через Vite proxy. В production backend обслуживает собранный frontend с того же origin. CORS для посторонних сайтов не включён; сессия использует HttpOnly cookie, записывающие запросы — CSRF-токен.

## Production-сборка

```sh
npm run build
npm start
```

Откройте **http://127.0.0.1:3000**. Для публикации за HTTPS reverse proxy задайте `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен` и `COOKIE_SECURE=1`. Создайте администратора до открытия публичного доступа.

```sh
docker compose up --build -d
```

Docker запускает приложение от непривилегированного пользователя, проверяет health endpoint и сохраняет базу в томе `mekan-data`. Docker-сборка требует установленного Docker; в текущей среде она не проверена.

## Реализованные сценарии

- Создание, просмотр, редактирование, поиск и фильтрация недвижимости и клиентов.
- Связанные сделки и показы; контроль ссылочной целостности и пересечений показов в пределах часа для одного объекта или клиента.
- Серверная пагинация списков, в том числе выбора объекта и клиента в формах.
- Подбор недвижимости с объяснением каждого критерия.
- Аналитика с серверной агрегацией: активные записи, этапы сделок, будущие показы и объём успешных сделок по валютам.
- Администратор создаёт сотрудников, меняет роли и отключает доступ. Отключение или изменение сотрудника отзывает его сессии.
- Смена собственного пароля с отзывом остальных сессий.
- Журнал создания, изменения и удаления записей, входов и изменения паролей; персональные значения полей и пароли в журнал не записываются.
- Оптимистическая блокировка: изменение устаревшей версии возвращает HTTP 409. Удаление требует `If-Match`.
- Адаптивный интерфейс, три языка, обработка загрузки, ошибок и пустых списков.

Роли: агент читает, создаёт и редактирует рабочие записи. Администратор дополнительно удаляет записи, управляет командой и читает журнал действий. Все сотрудники работают с общей базой одного агентства.

## Хранение и миграции

База по умолчанию: `data/mekan.sqlite`. `npm run db:migrate` применяет ожидающие миграции; при старте backend они также применяются автоматически. Уже применённая миграция повторно не запускается.

Первая миграция новой архитектуры умеет перенести базу предыдущей версии Mekan с JSON-карточками: сохраняет ID, записи, версии, связи и хеши паролей. Старые сессии аннулируются, требуется повторный вход. Миграция выполняется в транзакции с проверкой внешних ключей. **Перед обновлением существующей рабочей базы сделайте резервную копию.**

Денежные значения в SQLite хранятся целыми числами в сотых долях валюты. API принимает и возвращает суммы в основных единицах (например, `500000.25`). Валюты не конвертируются. Даты сохраняются в UTC, интерфейс отображает часовой пояс устройства.

Для простого резервного копирования остановите приложение и скопируйте весь каталог `data`. Не удаляйте Docker volume при обновлении.

## Конфигурация

Можно скопировать `.env.example` в `.env`. Backend загружает `.env`; Vite не получает секреты backend. В `npm run dev` launcher задаёт локальный `APP_ORIGIN` для порта 5173; явное значение из окружения shell имеет приоритет.

| Переменная      | По умолчанию            | Назначение                                                           |
| --------------- | ----------------------- | -------------------------------------------------------------------- |
| `HOST`          | `127.0.0.1`             | Адрес backend                                                        |
| `PORT`          | `3000`                  | Порт backend; Vite proxy ожидает 3000                                |
| `DB_PATH`       | `data/mekan.sqlite`     | База относительно корня проекта                                      |
| `APP_ORIGIN`    | `http://127.0.0.1:3000` | Единственный разрешённый origin для записи; dev launcher задаёт 5173 |
| `COOKIE_SECURE` | `0`                     | `1` для HTTPS                                                        |
| `NODE_ENV`      | `development`           | `production` включает production-настройки HTTP                      |
| `LOG_LEVEL`     | `info`                  | Уровень структурированных серверных логов                            |

Срок сессии — 7 дней. Пароли хешируются scrypt с отдельной солью; токены сессий сохраняются только в хешированном виде. Есть rate limiting, ограничения тела запроса, проверка Origin, CSRF и HTTP security headers. Cookie и токены скрываются в серверных логах. За reverse proxy лимит по IP применяется к адресу прокси; публичному серверу также нужен лимит запросов на уровне прокси.

## Интеллектуальный модуль

Это объяснимый рекомендательный алгоритм на правилах, **не обученная ML-модель**. Баллы не являются вероятностью сделки.

Предварительно отбираются доступные объекты с совпадающими типом недвижимости, видом сделки, валютой и периодом аренды. Далее:

| Критерий | Вес | Оценка                                                                                     |
| -------- | --: | ------------------------------------------------------------------------------------------ |
| Бюджет   |  40 | Полный балл до максимального бюджета; линейное снижение до нуля при двукратном превышении  |
| Район    |  25 | Совпадение без учёта регистра и крайних пробелов; полный балл, если предпочтение не задано |
| Комнаты  |  20 | Снижение пропорционально отклонению от запрошенного числа; 0 означает любое количество     |
| Площадь  |  15 | Полный балл при достижении минимальной площади, иначе пропорционально площади              |

Возвращаются 10 лучших вариантов. При равенстве баллов первым идёт более дешёвый объект. В карточке клиента видны баллы и отклонения по каждому критерию.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm audit
npm run test:smoke
```

Тесты используют отдельные временные базы. Покрываются авторизация и роли, CSRF/Origin, отзыв сессий, валидация, денежная точность, пагинация и поиск, конфликты версий, внешние ключи, пересечения показов, журнал, миграция старой базы, сохранение после рестарта, подбор, переводы и безопасный вывод пользовательского текста.

Визуальные браузерные проверки не заменяются этими тестами. В текущей среде служба управления браузером недоступна; перед публикацией выполните сценарии из [docs/QA.md](docs/QA.md).

## Границы текущей версии

Это работающая система одного агентства. Нет независимых организаций, восстановления пароля по email, загрузки документов и фотографий, внешних карт, платёжных интеграций и обученной модели оценки стоимости. Изображения явно помечены как иллюстрации категорий. Статусы объекта, клиента и сделки меняются отдельно. При росте нагрузки возможен переход на PostgreSQL через слой доступа к данным и новые миграции; сейчас PostgreSQL не подключён.

Подробнее: [архитектура](docs/ARCHITECTURE.md), [API](docs/API.md).
