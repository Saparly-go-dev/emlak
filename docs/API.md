# API v1

Базовый путь: `/api/v1`. Интерактивная спецификация: `/docs/`, JSON: `/docs/json`. Схемы запросов и ответов генерируются из общего пакета контрактов.

## Сессия

1. `GET /auth/session` возвращает `{ user, csrf, setupRequired }`.
2. При первом запуске `POST /auth/setup` принимает `{ name, email, password }`, создаёт администратора и устанавливает cookie. При повторной попытке — 409.
3. `POST /auth/login` принимает `{ email, password }`, возвращает сессию и устанавливает `mekan_session`.
4. Для последующих записывающих запросов передавайте cookie и заголовок `X-CSRF-Token` из ответа сессии.
5. `POST /auth/logout` отзывает текущую сессию.
6. `POST /auth/password` принимает `{ currentPassword, newPassword }`, отзывает старые сессии и возвращает новую с новым CSRF-токеном.

Браузер отправляет cookie автоматически с того же origin. Swagger UI позволяет выполнить вход, затем вставить `csrf` в схему авторизации `csrf`. Для внешнего HTTP-клиента используйте cookie jar. Записывающие запросы с браузерным Origin должны соответствовать `APP_ORIGIN`.

## Ресурсы

Для `properties`, `clients`, `deals`, `viewings`:

| Метод  | Путь            | Результат                                                     |
| ------ | --------------- | ------------------------------------------------------------- |
| GET    | `/{entity}`     | Пагинированный список                                         |
| POST   | `/{entity}`     | Новая запись, HTTP 201                                        |
| GET    | `/{entity}/:id` | Запись по ID                                                  |
| PUT    | `/{entity}/:id` | Полная замена редактируемых полей; обязательный `version`     |
| DELETE | `/{entity}/:id` | `{ ok: true }`; только администратор, обязательный `If-Match` |

Списки принимают `page` (от 1), `pageSize` (1–100, по умолчанию 20), `q`, `status`, `dealType` (`sale`/`rent`, для объектов и клиентов), `sort` (`newest`/`oldest`). Показы выводятся по дате встречи.

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "pageSize": 20,
  "pages": 0
}
```

Пример тела создания объекта:

```json
{
  "title": "Квартира в Ашхабаде",
  "address": "Адрес объекта",
  "district": "Aşgabat",
  "type": "apartment",
  "dealType": "sale",
  "currency": "TMT",
  "rentPeriod": "month",
  "rooms": 3,
  "price": 500000.25,
  "area": 100,
  "owner": "",
  "phone": "",
  "status": "available",
  "notes": ""
}
```

PUT принимает те же редактируемые поля плюс `version`. Не отправляйте служебные `id`, `createdBy`, `createdAt`, `updatedAt`: входные контракты строгие. Денежные значения имеют максимум два знака после запятой. Для аренды задаётся явный `rentPeriod`: `day` или `month`.

## Ошибки

```json
{
  "error": {
    "code": "conflict",
    "requestId": "req-42"
  }
}
```

Ошибка валидации может дополнительно содержать `fields`, где ключ — имя поля, значение — массив технических описаний. Интерфейс показывает локализованные сообщения, технические описания не переводятся автоматически.

| HTTP | Примеры кодов                                                                             |
| ---- | ----------------------------------------------------------------------------------------- |
| 400  | `validation`, `incompatible`                                                              |
| 401  | `unauthorized`, `invalidCredentials`                                                      |
| 403  | `forbidden`                                                                               |
| 404  | `notFound`                                                                                |
| 409  | `conflict`, `inUse`, `scheduleConflict`, `emailExists`, `setupComplete`, `selfDeactivate` |
| 413  | `tooLarge`                                                                                |
| 429  | `tooManyAttempts`                                                                         |
| 500  | `serverError`                                                                             |

`requestId` позволяет найти запрос в серверных логах. Стек ошибки не передаётся клиенту. Получив 409, перечитайте запись и предложите пользователю повторить изменение на свежей версии.
